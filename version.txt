Provisioning Network Gemini System 网络自动化部署系统 - Bug 修复与功能改进日志
版本 1.0 - 初始实现
功能： 基于自定义分层标记（#、##、###、####）的配置文件解析与 Netmiko 部署。

已知问题： 配置文件格式严格，对空行和标记位置敏感，容易导致解析失败。

版本 1.1 - 修复：配置文件解析失败问题
问题描述： 程序日志显示“共发现 0 个设备”，无法正确解析 devices.txt 文件。

根本原因： 自定义配置文件格式中，标记符（如 #、##、###）的缺失或位置错误，导致解析器无法正确分段。

解决方案： 明确了正确的配置文件格式规范，要求每个命令集、命令类别和设备块都必须严格以对应的标记符结束。（这是一个配置语法问题，而非程序代码问题）

版本 1.2 - 改进：升级至 YAML 配置文件
问题描述： 自定义文本格式因其严格性、易出错和扩展性有限，不适用于复杂场景。

解决方案： 1.  将配置文件格式从自定义文本迁移到行业标准的 YAML 格式。
2.  修改 src/core/config_parser.py，使其使用 PyYAML 库进行解析，从而增强了配置文件的可读性、健壮性和可扩展性。
3.  更新 main.py，默认读取 devices.yaml 文件。

版本 1.3 - 修复：文件路径解析错误
问题描述： 程序无法找到配置文件，日志显示在错误的目录（项目根目录的上一级）查找文件。

根本原因： main.py 中的路径解析逻辑使用 Path(__file__).resolve().parent.parent，导致路径错误地跳到了项目目录之外。

解决方案： 将路径解析逻辑修改为更稳健的 Path(__file__).resolve().parent，确保无论从哪个位置运行脚本，都能正确地定位到项目根目录下的 configs、logs 和 outputs 文件夹。

版本 1.4 - 修复：ping 命令执行超时
问题描述： 执行 ping 命令时，Netmiko 报出“Pattern not detected”错误，导致命令执行失败。

根本原因： ping 命令的动态输出和较长的执行时间，使得 Netmiko 在等待提示符时超时。

解决方案： 1.  在 src/core/device_manager.py 中，为 ping 命令添加特殊处理逻辑。
2.  将 ping 命令的 read_timeout 增加到 60 秒，为设备响应留出充足时间。
3.  将 ping 命令保留在 show 命令集中，以符合 YAML 配置文件的结构。
4.  同时，在 ConnectHandler 中增加了 global_delay_factor 参数，以提高整体连接的稳定性。

版本 1.5 - 功能：实时终端输出
问题描述： 在部署过程中，用户无法即时看到设备执行命令后的输出，影响调试和监控。

解决方案： 1.  在 src/core/device_manager.py 中，将 send_config_set 和 send_command 的返回值直接通过日志系统打印到终端。
2.  在输出前后增加了“--- 设备实时输出开始/结束 ---”标记，使终端输出更加清晰易读。

Network Automation Deployment System - Bug Fix and Feature Log
Version 1.6 - Bug Fix: Incorrect Report Output
Problem: The system was incorrectly generating detailed reports. The JSON output for each device was being overwritten, while the text (TXT) file was only saving the details of the last device.

Root Cause: The generate_detailed_reports method in src/core/result_handler.py used a non-unique filename inside the loop. This caused each iteration to overwrite the output file instead of creating a new one for each device.

Solution: The code was modified to ensure that each device's detailed report gets a unique filename. The new filename now includes the device's IP address and a timestamp ({device_ip}_report_{timestamp}.json/txt). This guarantees that every report is saved correctly, without overwriting previous ones.
